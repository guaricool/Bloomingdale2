# Bloomingdale2 — Spec v0.1 (MVP)

> Status: draft para revisión antes de team plan de construcción
> Última edición: 2026-06-10
> Owner: secretario de la rama + Mavis

## 1. Visión

Eliminar el trabajo manual del sábado (armar agenda, buscar himnos por número, llevar el control de quién ya discursó, recordar qué eventos anunciar). El sistema arma la agenda solo, el admin supervisa.

**Una frase**: dashboard dinámico para la Rama Bloomingdale 2 que automatiza la agenda dominical, los himnos, los anuncios y el tracking de discursos.

## 2. Personas

- **Admin** (secretario, presidente, 1er/2do consejero) — crea agendas, gestiona miembros, crea eventos, ve métricas
- **Miembro** (hermano/a de la rama) — ve agenda del día, abre himnos, ve anuncios y eventos

## 3. Features MVP (v0.1)

### F1 — Directorio de miembros
- CRUD: nombre, apellido, número de miembro (opcional, manejado como PII), grupo familiar
- Auto-crecimiento: cuando el admin asigna un discursante nuevo, se crea el miembro si no existe
- Búsqueda con auto-completado por nombre, apellido o número

### F2 — Agenda dominical
- Admin crea agenda para una fecha (debe ser domingo; validación)
- Estructura ordenada:
  1. Himno de apertura
  2. Invocación (quien ora, opcional)
  3. Anuncios (ver F4)
  4. Primer discurso (hermano + tema)
  5. Himno intermedio / sacramental
  6. Segundo discurso (hermano + tema)
  7. Himno de cierre
  8. Bendición (quien ora, opcional)
- Estados: `draft` → `published` → `completed`
- Constraint: una sola agenda por domingo

### F3 — Himnos
- Input: número (1–341)
- Auto-completado del nombre desde tabla local con los 341 himnos en español (solo metadatos: número, título en español, título en inglés opcional)
- Display: **pop-up con iframe a la URL oficial** `https://www.churchofjesuschrist.org/media/music/collections/hymns?lang=spa&number={N}`
- Fallback: link "Abrir en pestaña nueva" si el iframe no carga
- No almacenamos letras localmente (copyright limpio)

### F4 — Anuncios auto-generados desde eventos
- Admin crea un **evento**: título, descripción, fecha, tipo (actividad, evento especial, etc.)
- El sistema calcula los **domingos entre hoy y la fecha del evento**
- El evento aparece como **anuncio** en cada agenda de esos domingos
- Después de la fecha del evento: el anuncio desaparece automáticamente
- Anuncios manuales también posibles (con fecha de expiración opcional)

**Ejemplo concreto**: crear "La Noche Internacional" para 2026-07-17.
- Hoy = 2026-06-10 (miércoles)
- Domingos entre hoy y el evento: 06/14, 06/21, 06/28, 07/05, 07/12
- El evento aparece como anuncio en las agendas de esos 5 domingos
- El 07/18 (domingo siguiente al evento) ya no aparece

### F5 — Tracking de discursos
- Por cada miembro: fecha del último discurso, total acumulado
- Dashboard admin: lista ordenada por "tiempo sin discursar" (descendente)
- Filtros: "no ha discursado nunca", "no ha discursado en 3+ meses", etc.
- Vista rápida: candidatos a invitar a discursar

### F6 — Dashboard del miembro
- Vista principal del usuario logueado
- Muestra la agenda del **domingo actual** (si existe) o el **próximo**
- Secciones:
  - **Hoy / Próximo domingo**: la agenda, en orden, con click en himno para pop-up
  - **Eventos próximos**: lista de eventos del calendario
  - **Himnos**: buscador por número
  - **Miembros**: directorio lectura (opcional)

### F7 — Auth y roles
- Roles: `member`, `admin`
- `admin` ve un **tab extra "Administración"**
- En administración:
  - Crear/editar agendas
  - Gestionar miembros
  - Crear eventos
  - Ver tracking de discursos
  - Promover a otro usuario a `admin`
- Seed: el primer usuario registrado es admin (secretario)
- El admin puede promover a presidente / 1er consejero / 2do consejero

## 4. Out of scope (v0.1)

Explícitamente fuera del MVP, candidatos a v0.2+:
- Feed social / posts / comentarios
- Integración de lecciones "Ven, sígueme" (Come Follow Me)
- Calendario con vista mes
- Notificaciones push / email
- Multi-rama
- App móvil nativa
- Vista de "escuela dominical" / clases del domingo

## 5. Stack propuesto

| Capa | Tecnología | Por qué |
|---|---|---|
| Frontend + Backend | **Next.js 14** (App Router) + TypeScript | Un solo codebase, file-based routing, server actions, deploy simple |
| DB | **SQLite** (better-sqlite3) | Local, sin setup, backup = copiar archivo, sobra para 30–80 miembros |
| Estilos | **Tailwind CSS** | Iteración rápida, sin design system que mantener al inicio |
| Auth | **Auth.js (NextAuth)** + credentials + JWT | Liviano, sin vendor lock-in, fácil de extender |
| Forms / validación | **react-hook-form + zod** | Tipos compartidos cliente/servidor |
| i18n | Hard-coded en **español (es-MX)** | Una sola audiencia, i18n metería complejidad gratis |
| Real-time-ish | **Polling cada 30s** en la vista de agenda | Suficiente para "anuncios cambian a última hora" sin WebSocket |
| Hosting | **Local en laptop del secretario** (v0.1) → **VPS pequeño** (v0.2) si la presidencia quiere acceso remoto | Privacidad + costo $0 al inicio |

## 6. Modelo de datos (resumen)

```
Member       (id, firstName, lastName, membershipNumber?, familyGroupId?, createdAt, updatedAt)
FamilyGroup  (id, name, headMemberId?, createdAt)
Agenda       (id, date [unique, must be Sunday], status, createdBy, createdAt, updatedAt)
AgendaItem   (id, agendaId, type [hymn|speaker|prayer|announcement], order, refId, note?)
Hymn         (number [PK 1-341], titleEs, titleEn?)
Event        (id, title, description?, eventDate, type, createdBy, createdAt)
DiscourseLog (id, memberId, agendaId, discourseDate, topic?)
User         (id, email, passwordHash, role, memberId?, createdAt)
```

Nota: `membershipNumber` se almacena **hasheado o cifrado**, o simplemente no se almacena en MVP (se puede reconstruir al ingresar). Decisión en implementación.

## 7. Flujos clave

### Flujo A — Admin crea la agenda del domingo
1. Login → tab "Administración" → "Nueva agenda" → elige fecha (selector de fecha; si no es domingo, rechaza)
2. Click "Agregar himno de apertura" → ingresa número → autocompleta nombre → click "Agregar"
3. Click "Agregar discursante" → escribe nombre → si existe, autocompletado y selecciona; si no, "¿agregar como nuevo miembro?" → llena nombre y guarda
4. Repite para los demás himnos y el segundo discursante
5. **Anuncios** se muestran automáticamente según F4 (no los escribe a mano, los toma de eventos próximos)
6. Puede agregar anuncios manuales con fecha de expiración
7. "Guardar borrador" → "Publicar" cuando esté lista
8. El domingo siguiente (o el mismo domingo) → "Marcar como completada"

### Flujo B — Miembro abre la agenda del domingo
1. Login → dashboard
2. Vista "Hoy / Próximo domingo" muestra la agenda en orden
3. Click en himno → modal con iframe de la página oficial
4. Click en anuncio → expande descripción
5. La página **polling cada 30s** para refrescar anuncios (por si el admin agregó uno de último momento)

### Flujo C — Admin crea un evento
1. Tab "Administración" → "Eventos" → "Nuevo evento"
2. Llena título, descripción, fecha
3. El sistema calcula domingos entre hoy y la fecha
4. Para cada uno:
   - Si ya hay agenda publicada → inserta el item de anuncio en orden (al inicio de la sección "Anuncios")
   - Si no hay agenda → queda pendiente (cuando se cree la agenda, se incluirá)
5. Después de la fecha del evento → el item se marca como expirado y no se muestra

## 8. Done criteria (v0.1)

El MVP está listo cuando:
- [ ] Un admin puede registrarse y queda con rol `admin`
- [ ] Un admin puede crear una agenda para un domingo con himnos, discursos, y anuncios manuales
- [ ] Al meter número de himno, autocompleta el nombre desde la tabla de 341 himnos
- [ ] Click en himno abre la página oficial en modal
- [ ] Al crear un evento a futuro, el sistema lo agrega como anuncio a las agendas de los domingos previos
- [ ] Después de la fecha del evento, el anuncio ya no aparece
- [ ] Dashboard admin muestra lista de miembros ordenada por "tiempo sin discursar"
- [ ] Solo usuarios con rol `admin` ven el tab "Administración"
- [ ] Un admin puede promover a otro usuario a `admin`
- [ ] UI completa en español
- [ ] Build pasa, lint pasa, smoke test E2E pasa (login → crear agenda → publicar → ver como miembro)

## 9. Riesgos y mitigaciones

| Riesgo | Mitigación |
|---|---|
| Copyright himnos | No almacenamos letras; iframe a la fuente oficial |
| PII (números de miembro) | Hashear o no almacenar en MVP; documentar en AGENTS.md |
| Single point of failure (laptop) | Backup automático semanal de la DB SQLite a un drive/USB |
| Adopción baja (solo el secretario lo usa) | Empezar con el flujo de admin; el miembro lo adopta cuando vea valor |
| Date/timezone bugs con "domingos" | Usar `date-fns-tz` o almacenar la zona horaria explícita; tests |
| Iframe bloqueado por CSP de la iglesia | Fallback automático a "abrir en pestaña nueva" |
