## 4. Modelo de datos

9 tablas (8 originales + Post). Mismas columnas en SQLite (dev) y Postgres (prod).

| Tabla | Propósito | Campos clave |
|---|---|---|
| `User` | Cuentas con login | email (unique), passwordHash, role (`member`/`admin`), memberId (FK opcional) |
| `Member` | Miembros de la rama | firstName, lastName, membershipNumber (PII), familyGroupId (FK) |
| `FamilyGroup` | Grupo familiar | name, headMemberId (FK a Member) |
| `Agenda` | Agenda dominical (1 por domingo) | date (unique, YYYY-MM-DD), status (`draft`/`published`/`completed`), createdBy (FK) |
| `AgendaItem` | Items de la agenda (himno, discurso, oración, anuncio) | agendaId, type, "order", refId, note |
| `Hymn` | Himnos en español (1..341) | number (PK), titleEs, titleEn |
| `Event` | Eventos / actividades | title, description, eventDate, type (`actividad`/`evento_especial`/`servicio`/`reunion`/`otro`) |
| `DiscourseLog` | Histórico de discursos | memberId, agendaId, discourseDate, topic |
| `Post` | Feed público | authorId (FK), title, body, pinned (0/1) |

**Diferencias menores SQLite vs Postgres:**
- En Postgres los nombres de tabla se lower-casean sin comillas; con comillas dobles se respeta el case. El código actual usa quoting (`"User"`, `"Member"`, etc.) para portabilidad.
- `INTEGER PRIMARY KEY AUTOINCREMENT` → `INTEGER GENERATED ALWAYS AS IDENTITY PRIMARY KEY`
- `datetime('now')` → `CURRENT_TIMESTAMP`
- `result.lastInsertRowid` en Postgres es `null`; el wrapper re-SELECTea por id.

## 6. Sistema de auth

- **NextAuth v5 (Auth.js)** con Credentials Provider
- **Split config** (recomendación oficial v5):
  - `auth.config.ts`: edge-safe, sin DB, usado por middleware
  - `auth.ts`: Node, importa `getDb` y hace la query del user
- **JWT sessions** (no DB session lookup) — el payload del JWT incluye `id`, `role`, `memberId`
- **Primer user registrado = admin** (business rule en `app/api/register/route.ts`)
- Helpers en `lib/authz.ts`: `currentUser()`, `isAdmin()`, `requireAdmin()`, `requireAdminForPage()`, `requireSessionForPage()`, `AuthzError` class
- Helpers en `lib/api-guard.ts` (espejo para API routes): `requireUser()`, `requireAdmin()`

## 7. Capa de datos (`lib/db.ts`)

Wrapper dual-mode **async**:

```ts
import { getDb } from "@/lib/db";
const sql = getDb();
const rows = await sql.prepare("SELECT * FROM \"Member\" WHERE id = ?").all(id);
const row = await sql.prepare("SELECT * FROM \"Member\" WHERE id = ?").get(id);
const result = await sql.prepare("UPDATE ... WHERE id = ?").run(...);
// result.changes → número de filas afectadas
// result.lastInsertRowid → null en Postgres (usar re-SELECT por id)
```

**Detección de modo:**
- Si `DATABASE_URL` empieza con `postgres://` o `postgresql://` → usa `postgres` (postgres-js) con SSL
- Si no → abre SQLite en el path del env (default `./data/bloomingdale.db`)

**Traducción de placeholders:** `?` → `$1, $2, ...` para Postgres, respetando strings y quotes.

**Production:** necesita `DATABASE_URL` apuntando al Transaction Pooler de Supabase (puerto 6543). El puerto directo 5432 NO funciona desde Vercel serverless (ENOTFOUND).
